# Pikmin Recomp Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A Qt/QML "Forest"-styled launcher (the only published artifact) that self-updates from
GitHub releases, checks the toolchain and the ROM, recompiles/installs the game from the matching
source tag, and plays it — Linux and Windows.

**Architecture:** `launcher/` is a standalone CMake project. Pure logic in `launcher/src/core/`
(no GUI: ROM check, version compare, release JSON, ninja progress, toolchain probe, paths) with
unit tests; `launcher/src/app/` has a `Launcher` QObject (state machine driving QProcess /
QNetworkAccessManager) exposed to QML; `launcher/qml/` the Forest UI.

**Tech Stack:** C++20, Qt 6 (Core, Network, Quick, QuickControls2), CMake, QtTest-free plain tests.

**Spec:** `docs/superpowers/specs/2026-11-23-launcher-design.md`

## Global Constraints

- Repo `noalexan/PikminRecomp`; API `https://api.github.com/repos/noalexan/PikminRecomp/releases/latest`;
  source `https://github.com/noalexan/PikminRecomp/archive/refs/tags/v<ver>.tar.gz` (`.zip` on Windows).
- Assets: `PikminRecompLauncher-<ver>-x86_64.AppImage`, `PikminRecompLauncher-<ver>-windows.zip`.
- Data dir: Linux `~/.local/share/pikminrecomp-launcher/`, Windows `%LOCALAPPDATA%/pikminrecomp-launcher/`; state `launcher.json`.
- ROM: magic 0xC2339F3D at 0x1C, ID `GPIP01`; SHA-1 of `main.dol` and `fst.bin` must equal the reference values (computed from the maintainer's disc in Task 2).
- Never run `sudo`; never update silently; a failed build keeps the previous `game/`.
- No Nintendo assets in the launcher.

## Review Focus

1. Wrong/odd ROM (NTSC `GPIE01`, RVZ/NKit, truncated file, a directory): clear message, no crash — `rom_test` cases.
2. Build cancelled or failing mid-way: previous game still playable, state says "needs rebuild" — Task 3 human check.
3. No network / GitHub rate-limit: launcher works offline with "couldn't check for updates" — `release_test` parse failure case + human check.
4. Paths with spaces/non-ASCII (Windows user names): QProcess with argument lists, never shell strings — code review.
5. Launcher run from a read-only location (AppImage mount): self-update writes next to `$APPIMAGE`, not the mount — Task 4.

### Task 1: Core logic + tests
**Files:** `launcher/CMakeLists.txt`, `launcher/src/core/{rom,version,release,progress,toolchain,paths}.{hpp,cpp}`, `launcher/tests/core_test.cpp`.
- `RomResult check_rom(const QString& path)` → `{ok, gameId, message, dolSha1, fstSha1, imageSha1}`; reads header (0x440), FST offset/size at 0x424/0x428, DOL offset at 0x420 and DOL size from its section table; refuses RVZ (`RVZ\x01`), NKit (`NKIT` at 0x200), directories, short files.
- `int compare_versions(QString a, QString b)` (`v1.2.0` style); `std::optional<Release> parse_release(QByteArray json, QString platform)` → `{version, assetUrl, assetSize, sha256 (from body "sha256 <name> <hex>" lines)}`.
- `std::optional<std::pair<int,int>> parse_ninja_progress(QString line)` (`[123/4567] ...`).
- `ToolStatus probe_tool(QString name, QStringList versionArgs, QString minVersion)`; `QString install_hint(QStringList missing, OsFlavor)` (dnf/apt/pacman/msys2 lines).
- [ ] Tests first (`core_test`): GPIP01 real ISO accepted (skip without `~/Downloads/GPIP01/game.iso`); a header with `GPIE01` rejected with "NTSC"; truncated → message; version compare; release JSON sample; ninja line. FAIL → implement → PASS. Commit `feat(launcher): core checks`.

### Task 2: ROM reference values
- [ ] Compute SHA-1 of `main.dol` / `fst.bin` from `orig/GPIP01/sys/` and put them in `rom.cpp`; test asserts the real ISO matches. Commit with Task 1.

### Task 3: Launcher object + build pipeline
**Files:** `launcher/src/app/launcher.{hpp,cpp}`, `launcher/src/main.cpp`.
- QObject `Launcher` with Q_PROPERTYs: `version`, `latestVersion`, `updateAvailable`, `toolchainOk`, `toolchainText`, `romOk`, `romText`, `isoPath`, `gameState` (`none|built|outdated`), `builtVersion`, `busy`, `progress` (0..1), `stepText`, `log`; Q_INVOKABLEs `chooseIso(url)`, `build()`, `cancel()`, `play()`, `update()`, `refresh()`.
- Build = QProcess chain per spec (download source → extract → configure → build → install → swap). State in `launcher.json`.
- [ ] Human check: Linux full build from the local checkout via `PIKMIN_LAUNCHER_SOURCE=<dir>` override (skips download) reaches PLAY and runs the game.

### Task 4: Self-update
- [ ] `update()`: download asset, verify size/sha256, replace (`$APPIMAGE` on Linux; rename-swap on Windows), restart with `QProcess::startDetached`. Unit test for the sha256 line parser in Task 1's test.

### Task 5: Forest UI (QML)
**Files:** `launcher/qml/{Main,GlassPanel,StatusRow,PillButton,ForestBackground}.qml`, font `launcher/assets/Nunito-*.ttf` (OFL) — or system sans if unavailable offline.
- [ ] Screenshot (`QT_QPA_PLATFORM=offscreen` + `QQuickWindow::grabWindow` via `--screenshot PATH`) for the human check.

### Task 6: Packaging + docs
- [ ] `launcher/packaging/appimage.sh` (linuxdeploy + qt plugin if available, else a plain tarball), `launcher/packaging/windows.sh` (MinGW cross build + copy Qt DLLs/plugins/QML). CLAUDE.md section. Commit.
